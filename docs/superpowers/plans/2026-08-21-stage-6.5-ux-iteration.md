# Этап 6.5: UX-итерация гостевого фронта + десктоп — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Десктопная версия с сеткой месяцев на год, гейт «войди, чтобы выбрать даты» с сохранением клика, вкладка «Мои брони» (подвкладки Активная/История, редактирование комментария), имена гостей и своя-зелёная только залогиненным, лимит 14 ночей, набор случайных приветствий, маска телефона `+7`, тёплые тексты.

**Architecture:** Бэкенд — точечные добавки в существующие пакеты: `booking/` (лимит ночей, статус COMPLETED с ленивым условным UPDATE, PATCH комментария), `calendar/` (обогащение имени/`mine` только при сессии), `user/` (таблица `user_greetings` вместо колонки, случайная выдача), V6-миграция. Фронтенд — App.tsx распадается на страницы под react-router (`/` и `/my-bookings`), календарь становится списком месяцев (мобилка — окно 2 со стрелками, десктоп — сетка на год), справа на десктопе панель профиля.

**Tech Stack:** Spring Boot 4.0.7 (Jackson 3 — `tools.jackson`), Flyway, Testcontainers; React 19 + TS + Vite, TanStack Query, react-router v7, Tailwind v4, Vitest + RTL + MSW.

**Spec:** `docs/specs/2026-08-21-stage-6.5-ux-iteration-design.md`

-- Набор приветствий гостя (замена users.greeting): случайное показывается на каждый /api/me
CREATE TABLE user_greetings (
    id      BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id BIGINT       NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    text    VARCHAR(300) NOT NULL
);
CREATE INDEX idx_user_greetings_user ON user_greetings (user_id);

-- Существующее одиночное приветствие переезжает первой строкой набора
INSERT INTO user_greetings (user_id, text)
SELECT id, btrim(greeting) FROM users
WHERE greeting IS NOT NULL AND btrim(greeting) <> '';

ALTER TABLE users DROP COLUMN greeting;

-- COMPLETED = состоявшаяся поездка (история посещений, этап 6.5).
-- Прошедшие CONFIRMED уходят из GiST-исключения и из one_confirmed_booking_per_user —
-- история копится, а новая бронь не упирается в частичный уникальный индекс.
ALTER TABLE bookings DROP CONSTRAINT bookings_status_check;
ALTER TABLE bookings ADD CONSTRAINT bookings_status_check
    CHECK (status IN ('PENDING_OTP', 'CONFIRMED', 'CANCELLED', 'COMPLETED'));
```

public void setGreetings(long id, List<String> greetings) {

export function phoneDigits(raw: string): string {
  let d = raw.replace(/\D/g, '')
  if (d.length >= 11 && (d.startsWith('7') || d.startsWith('8'))) d = d.slice(1)
  return d.slice(0, 10)
}

export function formatPhone(digits: string): string {
  if (digits === '') return ''
  const p = [digits.slice(0, 3), digits.slice(3, 6), digits.slice(6, 8), digits.slice(8, 10)]
  let out = '+7 (' + p[0]
  if (digits.length > 3) out += ') ' + p[1]
  if (digits.length > 6) out += '-' + p[2]
  if (digits.length > 8) out += '-' + p[3]
  return out
}

export function toApiPhone(digits: string): string {
  return '+7' + digits
}
```
