# Этап 6.5: UX-итерация гостевого фронта + десктоп — дизайн

Дата: 2026-08-21. Статус: одобрен владельцем (брейншторминг с визуальным
компаньоном, 2026-08-21). Источник требований: список UX-замечаний
владельца после живого теста этапа 6 с телефона и компьютера.
Родительские спеки: `2026-08-13-japan-guest-booking-design.md`,
`2026-08-20-stage-6-frontend-guest-design.md`.
Мокапы сессии: `.superpowers/brainstorm/85698-*/content/` (не в git).

Разбивка списка замечаний (решение владельца): этап 6.5 — гостевой фронт
(эта спека) → этап 6.6 — переработка бота (один код активации, кнопки,
бронирование из бота, заявка для чужих) → этап 7 — админка (списки,
заявки, сортировки, Excel). Порядок подтверждён.

## 1. Цель и скоуп

Довести гостевой сайт по замечаниям владельца: полноценная десктопная
версия, гейт «войди, чтобы выбрать даты», вкладка «Мои брони» с историей,
имена гостей на занятых датах, лимит брони 2 недели, набор случайных
приветствий, маска телефона, тёплые тексты.

**В скоупе:** только гостевой фронт + необходимые бэкенд-добавки
(календарь с именами, `/api/me/bookings`, комментарий брони, лимит
14 ночей, `user_greetings` V6, admin-API набора приветствий).

**Вне скоупа:** бот (этап 6.6), админ-UI (этап 7, включая UI управления
приветствиями), rate-limit/XFF/Secure-cookie и прочий hardening (этап 8).

## 2. Календарь и доступ

- **Неавторизованный** видит календарь с занятостью (без имён) и кнопку
  «Войти» наверху. Клик по любой дате → модалка «Войдите, чтобы выбрать
  даты» с той же `LoginCard` (вход + форма заявки при `UNKNOWN_PHONE`).
  Кликнутая дата запоминается: после успешного логина она применяется
  как заезд, гость продолжает выбор диапазона с того же места.
- **Горизонт — год:** календарь листается/прокручивается до +12 месяцев
  от текущего (бэкенд и так ограничивает окно 366 днями).
- **Лимит длины брони — 14 ночей** («не больше 2 недель»): бэкенд
  валидирует в create и reschedule → 400 `RANGE_TOO_LONG`; фронт не даёт
  выбрать выезд позже заезд+14 (недостижимые дни визуально гаснут,
  подсказка «максимум 2 недели»). Граница: ровно 14 ночей — можно.
- **Имена на занятых датах — только залогиненным.** `GET /api/calendar`
  при валидной сессии дополняет занятые дни полями `guestName` и
  `mine: boolean`; без сессии ответ как сейчас (только статусы). Имя
  гостя PENDING_OTP скрыто всегда (правило спеки 3.3 сохраняется).
  Клик по чужой занятой дате (залогиненным) → поповер «Гостит {имя} ·
  {даты диапазона}».
- **Своя бронь в календаре — зелёным** (стиль «своя» уже есть в палитре
  «Тёплой бумаги»), чужие — красным, как сейчас.

## 3. Лейаут

- **Десктоп (утверждён мокап A «сетка + панель»):** от брейкпоинта ~lg
  — сетка месяцев 2–4 в ряд (по ширине экрана, CSS grid
  auto-fill/minmax), справа фиксированная панель: приветствие, карточка
  активной брони («Перенести»/«Отменить»/«Ввести код»), плашка
  Telegram. Шапка: название, вкладки, «Выйти».
- **Мобилка:** одна колонка как сейчас; чинится лишний вертикальный
  скролл (белая полоса внизу на iPhone) — переход `100vh → 100dvh` /
  ревизия min-height у корневого лейаута.
- **Вкладки «Календарь» / «Мои брони»** в шапке — только залогиненным.
  В проект заходит **react-router**: `/` (календарь) и `/my-bookings`;
  этап 7 добавит `/admin` (перенос решения «роутер в 7» — сюда).

## 4. Вкладка «Мои брони»

Утверждён мокап B — подвкладки **«Активная» / «История»**:

- **Активная:** карточка брони (даты, статус-бейдж, комментарий
  с карандашом — инлайн-редактирование), кнопки «Перенести» (переводит
  на календарь в режиме выбора дат, как сейчас из профиля) и
  «Отменить» (подтверждение → OTP). PENDING_OTP — «Ввести код»/
  «Отменить». Нет брони — «выбери даты в календаре» со ссылкой.
- **История:** список состоявшихся поездок (CONFIRMED с выездом в
  прошлом), новые сверху: «{даты} · N ночей». Отменённые брони в
  историю не попадают.

**Бэкенд:**
- `GET /api/me/bookings` → `{active: BookingDto|null, history:
  [{startDate, endDate, nights}]}` (FRIEND, живость по паттерну этапа 5).
- `PATCH /api/bookings/active` `{comment}` (≤500, гость, своя активная
  бронь, без OTP — комментарий не критичное поле) → 204.

## 5. Форма, телефон, тексты

- **Маска телефона** в гостевом логине: `+7` зафиксирован, гость вводит
  10 цифр, на лету форматируется `+7 (778) 788-64-32`; в API уходит
  нормализованный `+7XXXXXXXXXX`. Вставка полного номера (`+7...`/`8...`)
  нормализуется. Админ-логина не касается.
- **Комментарий к брони** — placeholder: «Если едете парой или семьёй —
  напишите, кто приедет с вами». Остаётся необязательным.
- **После подтверждения OTP** — тёплый экран вместо короткого «готово»:
  «Мы очень вас ждём! Ближе к дате мы свяжемся с вами, чтобы уточнить
  детали поездки» + даты брони.

## 6. Набор приветствий (бэкенд)

- **Миграция V6:** таблица `user_greetings (id, user_id FK → users,
  text varchar(300) not null)`; существующие `users.greeting` переносятся
  первой строкой; колонка `users.greeting` удаляется.
- `GET /api/me`: поле `greeting` — случайный элемент набора (nullable,
  если набор пуст → фронт-фолбэк «Привет, {имя}!» как сейчас). Случайное
  выбирается на каждый запрос `/api/me` — «рандом при логине» получается
  сам собой.
- `PUT /api/admin/users/{id}/greetings` `{greetings: string[]}` —
  полная замена набора (ADMIN, @PreAuthorize + доменный 404); пустые
  и blank-строки отбрасываются (закрывает перенос «blank greeting →
  null» из ревью этапа 6). Пустой массив = стереть все. Старый
  `PATCH /api/admin/users/{id}` с полем `greeting` удаляется — им
  пользовался только владелец через curl, миграция тривиальна.
  UI управления — этап 7.

## 7. Тестирование

Бэкенд (интеграционные, по паттернам этапов 4–5):
- лимит 14 ночей: create/reschedule — 14 можно, 15 → `RANGE_TOO_LONG`;
- календарь: без сессии имён нет; с сессией — `guestName`/`mine`;
  имя PENDING_OTP скрыто;
- `/api/me/bookings`: active/history раскладка, отменённые не в истории;
- PATCH комментария: своя активная — 204, чужая/нет активной — отказ;
- V6/приветствия: перенос данных, случайная выдача, PUT-замена,
  blank-фильтрация.

Фронт (Vitest + RTL + MSW, date-тесты с `vi.setSystemTime`):
- гейт: клик по дате без сессии → модалка логина; после логина дата
  применена как заезд;
- лимит на фронте: выезд дальше 14 ночей не выбирается;
- поповер имени на занятой дате (и его отсутствие без сессии);
- вкладки/роутер: «Мои брони» видна только с сессией; подвкладки;
- редактирование комментария; маска телефона (ввод, вставка,
  нормализация); тёплый экран после confirm; рандомное приветствие
  (мок отдаёт разные — рендерится присланное).

## 8. Разбивка на сессии (~1 час)

1. Бэкенд: лимит 14 ночей + календарь с `guestName`/`mine` (TDD).
2. Бэкенд: V6 `user_greetings` + случайная выдача в `/api/me` +
   `PUT .../greetings`; удаление старого PATCH.
3. Бэкенд: `GET /api/me/bookings` + `PATCH /api/bookings/active`.
4. Фронт: react-router, вкладки, страница «Мои брони» (подвкладки,
   редактирование комментария).
5. Фронт: десктоп-лейаут (сетка месяцев + правая панель), фикс
   мобильного скролла, год вперёд.
6. Фронт: гейт логина с сохранением даты, поповер имён, своя бронь
   зелёным, лимит 14 ночей в выборе.
7. Фронт: маска телефона, placeholder комментария, тёплый экран,
   приветствия; полировка.
8. Учебный файл `docs/learning/06-5-ux-iteration.md` (см. §9),
   финальное ревью, PR.

## 9. Темы docs/learning/06-5 (кратко — владелец знает фронт)
