# Этап 6: Frontend — календарь и бронирование (гостевая часть) — дизайн

Дата: 2026-08-20. Статус: одобрен владельцем (брейншторминг с визуальным
компаньоном, 2026-08-20). Родительская спека:
`docs/specs/2026-08-13-japan-guest-booking-design.md` (§3.2, §3.3, §3.4, §6, §9).
Мокапы сессии: `.superpowers/brainstorm/28969-*/content/` (не в git).

## 1. Цель и скоуп

Гость проходит весь свой путь на сайте с телефона: смотрит календарь,
входит по номеру, бронирует с подтверждением кодом из Telegram, переносит
и отменяет. Незнакомец подаёт заявку на доступ. После этапа ссылку можно
раздавать друзьям.

**Владелец знает фронтенд** — учебные цели этапа сводятся к интеграционным
нюансам (httpOnly cookie, прокси, форматы дат), стек берём индустриальный
без учебных упрощений.

**В скоупе:** SPA `frontend/` (React + TypeScript + Vite); публичный
календарь; вход по номеру; форма заявки при «номер не найден»; создание
брони со шторкой и OTP-модалкой; перенос/отмена (OTP) и отмена
неподтверждённой; профиль с активной бронью и кастомным приветствием;
плашка «привяжи Telegram»; бэкенд-добавка для приветствий (V5,
`/api/me`, `PATCH /api/admin/users/{id}`); nginx-контейнер в профиль
`app`; CI-джоб frontend.

**Вне скоупа:** админка (этап 7 — роутер появится там же), e2e-тесты
(вне V1), деплой (этап 8), мультиязычность, SSR/SEO.

## 2. Стек и структура

- React 19 + TypeScript + Vite; **TanStack Query** (серверное состояние);
  **Tailwind CSS v4** (стили); календарь — **свой компонент** (статусы
  дней с бэкенда, диапазон заезд-выезд); без react-router (одна страница).
- `frontend/src`:
  - `api/` — `client.ts` (обёртка fetch: base `/api`,
    `credentials: 'same-origin'`, разбор `{code, message}` в типизированную
    `ApiError`), `types.ts` (DTO, зеркалящие бэкенд), `queries.ts`
    (хуки TanStack Query: календарь, me, мутации броней/логина/заявки).
  - `components/` — `Calendar`, `BookingSheet` (шторка), `OtpModal`,
    `LoginCard` (+ раскрывающаяся `AccessRequestForm`), `ProfileCard`,
    `TelegramHint`.
  - `lib/dates.ts` — единственное место конвертаций: ISO ↔ дд/мм/гггг,
    русские подписи месяцев, полуинтервал ночей.
- Инварианты: в API и состоянии — только ISO-строки; дд/мм/гггг — только
  в рендере. Ключи запросов: `['calendar', from, to]`, `['me']`; мутации
  инвалидируют оба.

## 3. Визуальные решения (утверждены по мокапам)

- **Стиль «Тёплая бумага»:** фон `#faf7f0`/подложки `#f1ece0`, чернильный
  текст `#2b2620`, акцент-«ханко» `#b3402e`, приглушённый `#8a8272`;
  занято — красная заливка, заблокировано — штриховка, своя бронь —
  зелёная (`#eef0e4`/`#5a6b3b`); заголовки serif (Georgia/сист. serif),
  текст — системный sans; скругления 10–24px, мягкие тени. Mobile-first:
  одна колонка (max-width ~28rem по центру на десктопе).
- **Главный экран:** шапка (название + вход/профиль), календарь на
  2 месяца со стрелками, легенда. Тап по свободному дню = заезд, второй
  тап = выезд (день выезда может совпадать с чужим заездом — полуинтервал;
  диапазон, задевающий занятое/заблокированное, не даёт выбраться).
- **Шторка снизу** после выбора дат: «Заезд дд/мм/гггг → выезд дд/мм/гггг
  · N ночей», комментарий (опционально, ≤500), «Забронировать», подпись
  «код придёт в Telegram». Если `willReplaceBooking` — предупреждение
  «заменит твою бронь дд/мм–дд/мм» до отправки кода.
- **OTP-модалка:** 6 ячеек с автофокусом, «Подтвердить», «Отправить
  новый (таймер 60с от `RESEND_TOO_SOON`/локального отсчёта)», «Отменить
  бронь» (`DELETE /api/bookings/pending`). Ошибки красным под ячейками:
  `INVALID_CODE` «Неверный код», `CODE_EXPIRED` «Код сгорел — отправь
  новый», `BOOKING_EXPIRED` «Бронь истекла — начни заново». Перенос и
  отмена используют ту же модалку (без кнопки «Отменить бронь» — там
  нечего чистить, вытеснение кода делает бэкенд).
- **Вход и заявка:** карточка «Вход для своих» с полем номера;
  `UNKNOWN_PHONE` → под ней раскрывается форма заявки (имя, «откуда ты
  меня знаешь», номер уже заполнен) → успех: «Заявка отправлена, владелец
  свяжется»; `ALREADY_MEMBER` → «этот номер уже в списке — просто войди»;
  `RATE_LIMITED` → «слишком часто, подожди минуту».
- **Профиль:** кастомное приветствие владельца, фолбэк «Привет, {имя}!»;
  карточка активной брони (CONFIRMED — зелёный бейдж «подтверждена»,
  PENDING_OTP — жёлтый «ждёт код» + кнопки «Ввести код»/«Отменить»);
  «Перенести» (включает режим выбора дат в календаре) / «Отменить»
  (подтверждающий диалог → OTP); брони нет — «выбери даты в календаре».
  `TELEGRAM_NOT_LINKED` (и `telegramLinked=false` в `/api/me`) — жёлтая
  плашка со ссылкой на бота.

## 4. Кастомные приветствия (бэкенд-добавка)

- **Миграция V5:** `ALTER TABLE users ADD COLUMN greeting VARCHAR(300)`
  (NULL = нет кастомного).
- `GET /api/me` дополняется полем `greeting` (nullable).
- `PATCH /api/admin/users/{id}` `{greeting}` (nullable — null стирает) →
  204; ADMIN-only, по паттерну этапа 5 (@PreAuthorize, доменный 404).
  UI редактирования — этап 7; до тех пор владелец задаёт через curl.
- Приветствие — plain text (никакого HTML), фронт рендерит как текст.

## 5. Интеграция и инфраструктура

- **Dev:** `vite dev` на :5173 с прокси `/api → http://localhost:8080`
  — same-origin, cookie работает, CORS в бэкенде не появляется.
- **Docker:** сервис `frontend` в профиле `app` docker-compose.dev.yml:
  multi-stage (node:22 `npm ci && npm run build` → nginx:alpine),
  nginx раздаёт статику и проксирует `/api` на `backend:8080`; порт 80→
  наружу 3000. Топология локального стека = будущий прод (этап 8
  переиспользует Dockerfile и nginx.conf).
- **CI:** третий джоб `frontend`: `npm ci`, `npm run lint` (eslint),
  `npx tsc --noEmit`, `npm test` (vitest, jsdom).

## 6. Тестирование (Vitest + React Testing Library + MSW)

Обязательные по мастер-спеке §9 и ключевые для флоу:
- календарь: занятые/заблокированные дни некликабельны; выбор диапазона;
  полуинтервал (выезд в день чужого заезда — можно); диапазон через
  занятый день — не выбирается;
- `lib/dates`: ISO ↔ дд/мм/гггг, подсчёт ночей — юнит-тесты;
- OTP-модалка: маппинг кодов ошибок на тексты, resend-таймер,
  «Отменить бронь» дёргает DELETE /pending;
- вход: `UNKNOWN_PHONE` раскрывает форму заявки; успешная заявка —
  сообщение; `ALREADY_MEMBER`/`RATE_LIMITED` — тексты;
- профиль: кастомное приветствие vs фолбэк; `willReplaceBooking` —
  предупреждение.
API мокается MSW (обработчики читают/пишут in-memory состояние — флоу
логин→бронь→confirm проходит сквозь).

4. Вход/профиль: LoginCard, форма заявки, ProfileCard с приветствием,
   TelegramHint.
5. Бронирование: выбор диапазона, шторка, OTP-модалка, create+confirm,
   resend, отмена pending.
6. Перенос/отмена активной брони; полировка состояний ошибок.
7. Docker (nginx) + короткий учебный файл
   `docs/learning/06-frontend-integration.md` (httpOnly cookie на фронте,
   same-origin прокси vs CORS, ISO-на-проводе/локаль-на-экране, MSW),
   финальное ревью, PR.
