# Этап 6.6 — ОТП на входе, инклюзивные брони, редизайн навигации

Дата: 2026-08-21. Основано на находках ручного тестирования этапа 6.5 (скриншоты в сессии).

## Цели

1. Закрыть дыру входа: сейчас любой, кто знает номер друга из вайтлиста, входит под ним без подтверждения.
2. Запретить заезд следующего гостя в день выезда предыдущего — и показывать это в календаре.
3. Переделать навигацию: десктоп без вкладок (всё на одном экране), мобила с сегмент-контролом; убрать дубли «выйти» и вкладку «История».
4. Мелкие UX-фиксы: курсор, пустая колонка у анонима, «Передумал», автозум на iOS, незакрывающаяся модалка входа.

## Не-цели

- СМС как запасной канал кода (только Telegram; непривязанным — инструкция).
- Изменение админ-логина (пароль остаётся как есть).
- Изменение семантики «ночей» в подсчётах (25→26 — по-прежнему 1 ночь).

## A. ОТП переезжает с подтверждения брони на вход

### Бэкенд (`backend-api`)

**`POST /api/auth/login { phone }`** — больше не выдаёт куку:
- rate-limit по IP как сейчас;
- номер нормализуется, ищется FRIEND в вайтлисте, иначе `UNKNOWN_PHONE` (флоу заявки на доступ не меняется);
- если `telegramChatId == null` → ошибка `TELEGRAM_NOT_LINKED` (фронт показывает инструкцию);
- иначе `OtpService.issue(user, "LOGIN", {})` (вытесняет старые челленджи, код в outbox → Kafka → бот) и ответ `202 Accepted`.
- Повторный вызов = повторная отправка кода; отдельного resend-эндпоинта нет, спам ограничен существующим `LoginRateLimiter`.

**`POST /api/auth/verify { phone, code }`** — новый эндпоинт:
- rate-limit по IP;
- находит FRIEND по номеру, проверяет активный челлендж `LOGIN` (TTL 5 минут, 3 попытки — та же механика `OtpService`, но верификация по `user_id + action`, без `booking_id`);
- успех → кука на 30 дней (существующий `authCookie`), `204`;
- ошибки — существующие коды: `INVALID_CODE`, `CODE_EXPIRED`, `NO_ACTIVE_CODE` (+ исчерпание попыток).

**Брони без кода:**
- `POST /api/bookings` вставляет сразу `status = 'CONFIRMED'`; конфликт по exclusion-констрейнту → 409 `OVERLAP` (как сейчас при подтверждении). Уведомление владельцу `BOOKING_CONFIRMED` уходит сразу.
- `PATCH /api/bookings/{id}` (перенос) и `DELETE /api/bookings/{id}` (отмена) выполняются сразу, без челленджа; уведомления владельцу — как при сегодняшнем успешном verify.
- Удаляются: `POST /bookings/{id}/confirm`, `POST /bookings/{id}/resend-code`, `DELETE /bookings/pending`, `PendingBookingCleaner`, действия `CREATE_BOOKING`/`RESCHEDULE`/`CANCEL` в `OtpService`-вызовах.
- `BookingStatus.PENDING_OTP` уходит из логики (из `/api/me`, `/api/me/bookings`, правил «одна активная»); значение в БД остаётся валидным, миграции по старым строкам не делаем.
- Ленивый `COMPLETED` не меняется.

### Бот (`bot-service`)

Не меняется: `OTP_CODE` обрабатывается как раньше, `action` в payload теперь `LOGIN`. Текст сообщения бота можно уточнить («код для входа»), но это косметика внутри существующего обработчика.

### Фронтенд

- `LoginCard` — два шага: (1) номер + «Войти» → `202`; (2) «Код отправлен в Telegram» + поле кода + «Подтвердить» (`/auth/verify`) + кнопка «Отправить ещё раз» (повторный login, disabled на минуту при `RATE_LIMITED`).
- `TELEGRAM_NOT_LINKED` → плашка с той же механикой, что `TelegramHint` (ссылка на бота из `VITE_BOT_URL`): «Мы шлём код входа в Telegram. Напиши боту, поделись контактом — и возвращайся». Текст самого `TelegramHint` обновляется: «код подтверждения» → «код входа». После этого изменения залогиненными бывают только привязанные пользователи, поэтому `TelegramHint` из `ProfileCard` удаляется — плашка живёт только в логин-флоу.
- После успешного `verify` модалка входа закрывается **всегда** (фикс бага: сейчас закрывается только при входе через клик по дате).
- `OtpModal` удаляется; статусы «ждёт код», кнопки «Ввести код»/«Отменить (pending)» удаляются из `ProfileCard` и «Моих броней». Экран «Мы очень вас ждём» показывается сразу после успешного создания/переноса брони.

## B. День выезда занят

- **Миграция V7**: `no_overlapping_bookings` пересоздаётся как `EXCLUDE USING gist (daterange(check_in, check_out, '[]') WITH &&)` с прежним фильтром по активным статусам. Прод-данных нет; если в дев-базе есть стыкующиеся брони, миграция упадёт — правится вручную.
- `BlockedPeriodService`: проверка пересечений становится инклюзивной по `check_out` (`checkIn <= end && checkOut >= start`).
- `CalendarService`: день `check_out` каждой активной брони отдаётся как `BOOKED` (с `mine`/`guestName` как у остальных дней брони).
- Фронтенд: подсветка выбранного диапазона включает день выезда; `checkoutCandidates` (клик в чужой день заезда как выезд) удаляется — выезд теперь любой свободный день в пределах лимита 14 ночей; сканирование «кто гостит» (`handlePickBusy`) продолжает работать по `guestName`.

## C. Навигация и мелкие фиксы

### Десктоп (`lg:`)

- Шапка: логотип + одна кнопка «выйти» (для залогиненного) или «Войти» (для анонима). Ссылок «Календарь / Мои брони» нет.
- Правая панель 22rem, отделена вертикальной линией (`border-l`): телефон, приветствие, карточка активной брони («Перенести»/«Отменить»), ниже — «Прошлые поездки»: нередактируемый список `история` из `/api/me/bookings`.
- Аноним: грид без правой колонки, календарь на всю ширину.
- `/my-bookings` на десктопе редиректит на `/`.

### Мобила

- Порядок: шапка (логотип + «выйти») → приветствие → сегмент-контрол «Календарь | Мои брони» (подсветка активной, роуты `/` и `/my-bookings`) → контент.
- Вкладка «Календарь»: только календарь (карточки брони нет; баннер переноса и «кто гостит» остаются).
- Вкладка «Мои брони»: активная бронь с кнопками и комментарием, ниже — нередактируемая история. Вкладки «История» нет.
- Флоу «Перенести» из «Моих броней» по-прежнему переключает на календарь с баннером переноса.

### Мелкие фиксы

- Глобально: `button:not(:disabled) { cursor: pointer }`.
- «Передумал» в баннере переноса — кнопка с рамкой (как «Оставить» в диалоге отмены), не текстовая ссылка.
- Инпуты/textarea: шрифт ≥ 16px на мобиле (убирает автозум iOS; сам зум не запрещаем).

## Тестирование

- Бэкенд: интеграционные тесты `login → 202 + outbox OTP_CODE(LOGIN)`, `verify` (успех/неверный/истёк/попытки/непривязанный Telegram), бронь сразу `CONFIRMED`, перенос/отмена без кода, инклюзивный констрейнт (стыкующаяся бронь → 409), календарь отдаёт день выезда как `BOOKED`.
- Фронтенд: правка существующих тестов (`LoginCard`, флоу-тесты, календарь, страницы) под новый двухшаговый вход, отсутствие `PENDING_OTP`, инклюзивную подсветку и новую навигацию.

## Порядок работ

1. Бэкенд A (auth-флоу) + тесты.
2. Бэкенд B (миграция, календарь) + тесты.
3. Фронтенд A+B (вход, удаление OTP-модалки, подсветка).
4. Фронтенд C (навигация, панель, мелкие фиксы) + правка тестов.
