# Операционная памятка — что настроить самому

Здесь всё, что нельзя автоматизировать в коде: секреты, номера, приветствия.
Актуально для локального запуска в Docker (`docker compose -f docker-compose.dev.yml --profile app up --build -d`).

> **Важно про UI.** Веб-админки пока нет (это этап 7). Поэтому добавление гостей,
> приветствия и одобрение заявок сейчас делаются **через SQL или curl**. Ниже — как.
> Когда появится админка (или одобрение через бота), станет кнопками.

---

## 1. Секреты и переменные окружения

### 1.1 Корневой `.env` (в git НЕ попадает)

Файл `/.env` в корне проекта. Его читают контейнеры `backend` и `bot`. Нужны:

```env
# Токен Telegram-бота — выдаёт @BotFather (см. раздел 5)
BOT_TOKEN=123456789:AA...ваш_токен_от_botfather

# Общий секрет для канала бот→бэкенд (/api/bot/**). Любая длинная случайная строка.
# Сгенерировать: openssl rand -hex 32
BOT_API_TOKEN=подставь_длинную_случайную_строку
```

- `BOT_TOKEN` — без него бот не запустится.
- `BOT_API_TOKEN` — без него эндпоинт `/api/bot/**` закрыт (401), и кнопки в боте
  («Мои записи»/«История») вернут «попробуй позже». **Одно и то же значение** уходит
  и в backend, и в bot — они сверяют его между собой.

### 1.2 `frontend/.env` (в git НЕ попадает; есть `frontend/.env.example`)

```env
# Ссылка на твоего бота, чтобы плашка «напиши боту» на сайте была кликабельной
VITE_BOT_URL=https://t.me/имя_твоего_бота
```

Если не задать — плашка покажет текст «напиши боту» без ссылки (не критично).
Меняется только при пересборке фронта (`docker compose ... up --build -d frontend`).

### 1.3 Боевые секреты (на будущее, этап 8 — деплой)

Сейчас в `backend-api/src/main/resources/application.yml` **dev-заглушки**, которых
достаточно для локального запуска, но НЕ для интернета:

| Что | Где сейчас | Для прода |
|---|---|---|
| JWT-секрет (`app.jwt.secret`) | `dev-secret-change-me-...` | заменить на длинный случайный, из env |
| Пароль админа (`app.admin.password`) | `admin-dev-password` | заменить на свой |
| Телефон админа (`app.admin.phone`) | `+818000000000` | см. раздел 2 |
| Пароль БД (`spring.datasource`) | `dev`/`dev` | заменить |

Пробрасывать их через env-переменные и `.env` — задача этапа 8 (деплой). Пока не трогай,
для локальной работы заглушки рабочие.

## 2. Админ — кто это и как войти

Админ сидируется автоматически при старте бэкенда из `app.admin.phone` +
`app.admin.password` (класс `AdminSeeder`, идемпотентный upsert по телефону).

**Сейчас админ = `+818000000000` / пароль `admin-dev-password`** (заглушки).

Вход админа — по паролю: `POST /api/auth/admin-login {phone, password}` (не беспарольный,
в отличие от гостей). Веб-формы для этого пока нет — только API (см. раздел 6).

### Хочешь свой номер как админ?

Есть нюанс: **номер админа не может одновременно быть гостем.** Беспарольный вход для
гостей (`/auth/login`) намеренно не пускает роль ADMIN. Твой номер `+77787886432` сейчас —
гость с активной бронью. Варианты:

- **Рекомендую:** держи для админа **отдельный номер** (можно оставить заглушку
  `+818000000000` или поставить второй свой номер). Тогда гостевой аккаунт остаётся гостевым.
- Либо поменяй `app.admin.phone` на свой номер и пересобери бэкенд — но тогда этот номер
  перестанет работать как гостевой.

Сменить телефон/пароль админа: правишь `app.admin.phone`/`app.admin.password` в
`application.yml` (или через env на этапе 8) и перезапускаешь бэкенд —
`AdminSeeder` обновит запись.

## 3. Белый список гостей — как добавить номер

Гость входит на сайт беспарольно, только если его номер **уже в белом списке**
(таблица `users`, роль `FRIEND`). Два способа добавить:

### Способ A — напрямую в БД (быстро, сейчас без UI)

```bash
docker compose -f docker-compose.dev.yml exec -T postgres \
  psql -U dev -d guestbooking -c \
  "insert into users(phone, name) values ('+77001234567', 'Айгуль');"
```

Роль по умолчанию `FRIEND`. Телефон — в международном формате с `+`.
Проверить список: `... psql -U dev -d guestbooking -c "select id, name, phone, role from users;"`

### Способ B — через API (когда войдёшь админом, см. раздел 6)

```
POST /api/admin/users   {"phone": "+77001234567", "name": "Айгуль"}
```

Гость после добавления заходит на сайт, вводит номер → получает код в Telegram
(если привязал бота) → входит.

## 4. Приветствия гостю («не просто Привет, Миша»)

У каждого гостя может быть набор приветствий; на каждый вход `/api/me` показывается
случайное. Хранятся в таблице `user_greetings`.

### Способ A — напрямую в БД

Сначала узнай `id` гостя (`select id, name from users;`), потом:

```bash
docker compose -f docker-compose.dev.yml exec -T postgres \
  psql -U dev -d guestbooking -c \
  "insert into user_greetings(user_id, text) values
     (2, 'С приездом, дорогой друг! 🏡'),
     (2, 'Ну наконец-то ты добрался!'),
     (2, 'Заходи, чайник уже греется ☕');"
```

(здесь `2` — id гостя). Удалить старые: `delete from user_greetings where user_id = 2;`

### Способ B — через API (админом)

```
PUT /api/admin/users/{id}/greetings   {"greetings": ["текст 1", "текст 2", ...]}
```

Заменяет весь набор. Пустой список — уберёт приветствия (тогда покажется «Привет, Имя!»).

## 5. Telegram-бот — создать и привязать

1. В Telegram найди **@BotFather** → `/newbot` → задай имя и username → получишь токен.
2. Впиши токен в корневой `.env` как `BOT_TOKEN` (раздел 1.1).
3. `VITE_BOT_URL=https://t.me/<username_бота>` в `frontend/.env` (раздел 1.2).
4. Перезапусти стек. Гость привязывает бота так: открывает бота → `/start` →
   «Поделиться контактом». Если номер в белом списке — бот пишет «Telegram привязан»
   и показывает кнопки меню. Если нет — «тебя пока нет в списке» + можно оставить заявку.

Коды входа и уведомления о бронях приходят в этот чат. Без привязанного Telegram гость
не сможет войти (код доставить некуда).

## 6. Как дёргать админ-API руками (пока нет UI)

Все `/api/admin/**` требуют админскую куку. Получить её и сохранить в `cookies.txt`:

```bash
curl -s -c cookies.txt -X POST http://localhost:8080/api/auth/admin-login \
  -H 'Content-Type: application/json' \
  -d '{"phone":"+818000000000","password":"admin-dev-password"}'
```

Дальше — с этой кукой:

```bash
# список заявок на доступ
curl -s -b cookies.txt "http://localhost:8080/api/admin/access-requests"
# одобрить заявку (гость станет гостем в белом списке)
curl -s -b cookies.txt -X POST "http://localhost:8080/api/admin/access-requests/1/approve"
# отклонить
curl -s -b cookies.txt -X POST "http://localhost:8080/api/admin/access-requests/1/reject"

# добавить гостя вручную
curl -s -b cookies.txt -X POST "http://localhost:8080/api/admin/users" \
  -H 'Content-Type: application/json' -d '{"phone":"+77001234567","name":"Айгуль"}'

# список гостей / броней / блокировок дат
curl -s -b cookies.txt "http://localhost:8080/api/admin/users"
curl -s -b cookies.txt "http://localhost:8080/api/admin/bookings"
```

## 7. Заявки на доступ — как работает поток

1. Незнакомый номер пытается войти на сайте → видит «этого номера нет в списке» → оставляет
   заявку (имя + «откуда меня знаешь»).
2. Тебе (админу с привязанным Telegram) прилетает уведомление о заявке в бота.
3. Ты одобряешь (`approve`) → человек добавляется в белый список → может войти.
   Или отклоняешь (`reject`).

Одобрение через **кнопки в боте** — это следующий шаг (часть B-2), пока только через API (раздел 6).
